# NuvioEdge agent guidance

## Execute by default

- For implementation, bug-fix, refactoring, build, and test requests, inspect the relevant code, make the smallest justified change, and validate it. Do not stop after proposing a plan.
- Keep any useful task checklist in the current agent. Complexity, multiple files, debugging, or a documentation update alone are not reasons to recommend or initiate a Plan/Architect handoff.
- Use a planning-only workflow when the user explicitly requests one. Ask a focused question only when a missing decision materially affects correctness, safety, or scope; otherwise follow established patterns and proceed.
- Honor explicit read-only requests, required approvals, and tool permission boundaries. Do not treat execution-first guidance as permission for destructive changes, publishing, or unrelated work.
- Memory Bank files and MCP memory tools are optional context, not prerequisites. Read only relevant notes, verify them against source, and continue if tools or notes are absent. Do not require status banners, initialize memory, or change agents just to update notes.

## Project map and constraints

- Android TV application: Kotlin, Jetpack Compose, Hilt, and coroutines. The main namespace is `com.nuvio.tv`; application IDs differ by distribution and build type.
- Keep shared code in `app/src/main`, distribution-specific implementations in `app/src/full` or `app/src/playstore`, and tests in the existing matching source sets. Preserve both flavors.
- Preserve the local playback AAR integration and stock Media3 exclusions in [app/build.gradle.kts](app/build.gradle.kts); consult [app/libs/README.md](app/libs/README.md) before changing player dependencies.
- Keep changes focused and follow the approval and PR requirements in [CONTRIBUTING.md](CONTRIBUTING.md). See [MODIFICATIONS.md](MODIFICATIONS.md) for fork-specific history and notices.

## Validation

- On Windows, use the Gradle wrapper from the repository root: `.\gradlew.bat`. Prefer the existing [VS Code build/test tasks](.vscode/tasks.json); do not launch a duplicate Gradle build while another is active.
- Run focused tests first. The `Stage 1: Focused IPTV and Live TV Tests` task targets the IPTV/live suites; the unit-test task is `:app:testFullDebugUnitTest`.
- For shared Android changes, use `Stage 2: Debug Flavor Builds` or the tasks `:app:assembleFullDebug :app:assemblePlaystoreDebug --no-daemon --console=plain` after focused validation.
- Resolve local build configuration using [local.example.properties](local.example.properties) and the Gradle files. Do not expose local properties, credentials, signing material, or authenticated stream URLs.
- Report checks actually run and any blockers; never claim an unexecuted build, test, or device check passed.

## Chat agent selection

- Select built-in **Agent** or **NuvioEdge Code** for implementation; **NuvioEdge Debug** also implements and tests fixes. **NuvioEdge Ask** and **NuvioEdge Architect** are opt-in, read-only roles.
- Repository instructions guide behavior; they cannot set the VS Code agent picker or override higher-priority runtime instructions. If chat remains in Plan, select Agent/Code in the picker. If discovery is wrong, inspect Chat customization diagnostics and the loaded instruction sources in a new chat.
